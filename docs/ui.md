# UI 方針

## 全体
- この文書はロードマップではなく、最終的に目指す UI の理想形を記述する設計書として扱う
- 全体を通して、スマホの縦画面での利用を前提に設計する
- 表示する情報は、ユーザが今ほしい情報に絞り、過不足のない情報量を目指す
- 1画面に情報を詰め込みすぎず、優先度の高い情報から上に配置する
- URL は `/` と room の 2URL 構成を基本とする
- room 配下では `待機画面` `ゲーム画面` `between_hands` の 3 状態を切り替えて扱う
- `待機画面` `ゲーム画面` `between_hands` は別画面として設計するが、URL は分けずに同じ room URL の中で状態切り替えとして扱う

## `/`
### 目的
- 初回訪問ユーザが、どんなゲームかをすぐ理解できること
- 部屋作成まで迷わず進めること

### 表示する内容
- タイトル: `銘柄ポーカー`
- 遊び方
  - ポーカーは心理戦
  - 強い手で勝つか、弱い手でも相手を降ろして勝つかで勝敗が決まる
  - このゲームでは数字が `0〜9` なので役ができやすく、よりアクションの多い展開になりやすい
- 部屋作成 UI
  - 部屋名入力テキストボックス
  - 部屋作成ボタン

### 方針
- 必要最低限の情報に絞る
- `/` はゲーム紹介と部屋作成に役割を限定する
- スマホ縦画面のファーストビューで、タイトル、短い説明、部屋作成 UI が収まる構成を優先する
- 説明は短い段落で読める形にし、最初に読まなくても部屋作成に進める構成にする
- `2〜6 人` `手札 2 枚 + 場札 5 枚` `SB / BB とベッティングあり` のような補助ラベルは置かない

## 待機画面
### 目的
- 参加者がゲーム開始前に必要な準備を迷わず完了できること
- 招待と参加状況の確認をしやすいこと
- ゲーム開始までの流れがすぐ分かること

### セクション構成
#### セクション 1
- 部屋名
- 共有導線
  - 共有用 URL の表示
  - 共有ボタンを主役にする
  - コピーボタンは補助として置く
  - この URL を送れば参加できることを短く伝える

#### セクション 2
- 待機者一覧
  - 6 人分の枠を常に表示し、空き枠も見えるようにする
  - 各枠には名前、接続状態、自分であることを示す表示を出す
  - `busted` のような表示は出さない
- 自分の名前編集
  - 自分の名前だけその場で編集できる
  - 決定ボタンは置かず、自動保存前提で扱う
- ゲーム開始ボタン
  - 2 人以上そろうと開始できることが分かるようにする
  - 誰が押しても開始できる前提で扱う

#### セクション 3
- ルール説明
  - 手札 2 枚と場札 5 枚で最強の 5 枚役を作ること
  - ゲームの流れを、手札確認、賭け、場札 3 枚公開、賭け、4 枚目公開、賭け、5 枚目公開、賭け、勝負の順で短く伝える
  - 全ての役を簡潔に載せ、強弱がひと目で分かるようにする

### ルール説明
- 手札 2 枚と場札 5 枚から最強の役を作る
- 各ラウンドで場札が増え、そのたびに賭けを行う
- 役一覧は簡潔にまとめ、強い順が分かる形にする

### 方針
- 待機画面は 3 セクションに絞り、意識が散らないようにする
- 共有、参加状況、開始導線を優先し、補足説明は下に置く
- ルール説明は初見ユーザが流れをつかめる最小限にとどめる
- `/` と内容を重ねすぎず、待機画面では参加直前に必要な要点だけを伝える

## ゲーム画面
### 目的
- いまのラウンドで必要な判断を、スマホの縦画面で迷わず行えること
- 情報量の多いポーカー画面でも、常時表示する情報を絞って見やすさを保つこと

### 基本方針
- 画面が小さいため、すべての情報を常時表示しようとしない
- 常時表示するのは、賭け判断に必要な情報に絞る
- それ以外の情報は削るか、必要最小限の簡易表示に寄せる
- 同じ情報を複数箇所に重ねて表示しない
- プレイヤー一覧は簡易表示を基本とする

### レイアウト
- ヘッダ
  - 現在のラウンドのみを表示する
  - 全ラウンドを並べて表示し、現在ラウンドを強調する
  - 固定表示は前提にしない
- メイン表示
  - 場札
  - 自分の手札
  - 参加者情報
- フッタ
  - アクション UI
  - 自分の番でないときは小さく折りたたむ

### 常時表示する内容
- 自分の手札
- 場札
- 自分のアクションボタン
- 現在の main pot
- 自分がコールに必要な額
- 各プレイヤーの残り stack
- 各プレイヤーがこのベッティングラウンドで入れている額
- 誰の手番か
- fold / all-in / 接続不良 などの状態

### ヘッダ
- 責務はラウンド表示だけに絞る
- `場札 0 / 3 / 4 / 5` を常時見せ、現在ラウンドを強調表示する

### フッタ
- 責務はアクションボタンだけに絞る
- 2 段階 UI を前提にする
  - 最初は `降りる` と `賭ける` の二択だけを出す
  - `賭ける` には最低参加費を数値で併記する
  - 参加を決めた後に、最低限の参加費、3 種の raise、3 種の bet、`All-in` を選べるようにする
- `check` `call` `bet` `raise` などの用語は基本的に表に出さず、数値中心で見せる
- raise は現在の最低参加費を基準に `2 / 3 / 4 倍`
- bet は pot を基準に `30 / 50 / 75%`

### メイン
- フッタとヘッダにない、賭けるために必要な最低限の情報を表示する
- 場札は可能な限り 1 行で収める
- 手札は場札との優先順位を見ながら、1 行または 2 行で最も見やすい構成を選ぶ
- 参加者情報は簡易表示を基本にし、裏向きカード UI は置かない
- 参加者情報では、残り stack、このラウンドの投入額、手番、状態がすぐ分かることを優先する

### アクション UI
- ポーカー用語は基本的に表示せず、初心者向けの短いラベルを使う
- アクションは状況に応じて表示内容を変える
- 主な操作は `降りる` `賭ける` `All-in` を基本にする
- 自由入力は設けず、数値ベースの候補のみを表示する
- ラウンドが進む条件を自然に伝える補助文を入れる
- 手札と場札の最終的な配置、役一覧の具体的な見せ方は別途詰める

## `between_hands`
### 目的
- 前のハンド結果を確認し、次のハンド開始までの待機を分かりやすくすること

### 方針
- `between_hands` は進行中のゲーム画面とは別の専用セクションとして扱う
- ハンドとハンドの間なので、進行中ハンド用の情報は表示しない
- `game_over` は `between_hands` の派生表示として扱う
- 通常の `between_hands` は次ハンド待ちを扱う
- `game_over` 時は最終順位表示と待機画面への導線を表示する

### 表示する内容
- 前のハンド結果
- 勝者
- 各プレイヤーの stack の増減
- ready 状況
- 次ハンド開始待ちの案内
- `game_over` 時は最終順位
- `game_over` 時は待機画面へ戻る導線

### 表示しない内容
- 自分の手札
- 場札
- 進行中ラウンド用のアクション UI
