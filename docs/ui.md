# UI 方針

## 全体
- この文書は現状実装の説明ではなく、今後目指す UI 方針を定めるための設計書として扱う
- 全体を通して、スマホの縦画面での利用を前提に設計する
- 表示する情報は、ユーザが今ほしい情報に絞り、過不足のない情報量を目指す
- 1画面に情報を詰め込みすぎず、優先度の高い情報から上に配置する
- URL は `/` と room の 2URL 構成を基本とする
- room 配下では `待機画面` `ゲーム画面` `between_hands` の 3 状態を切り替えて扱う
- `待機画面` `ゲーム画面` `between_hands` は別画面として設計するが、URL は分けずに同じ room URL の中で状態切り替えとして扱う

## `/`
### 目的
- 初回訪問ユーザが、どんなゲームかをすぐ理解できること
- 部屋作成まで迷わず進めること

### 表示する内容
- タイトル: `銘柄ポーカー`
- ゲームの説明
  - どんなゲームかを日本語で簡潔に説明する
  - 部屋を作って複数人で遊ぶゲームであることが伝わるようにする
- 部屋作成 UI
  - 部屋名入力テキストボックス
  - 部屋作成ボタン

### 方針
- 必要最低限の情報に絞る
- `/` はゲーム紹介と部屋作成に役割を限定する
- 説明は短くし、最初に読まなくても部屋作成に進める構成にする
- 部屋作成 UI は画面内ですぐ見つかる位置に置く

## 待機画面
### 目的
- 参加者がゲーム開始前に必要な準備を迷わず完了できること
- 招待と参加状況の確認をしやすいこと
- ゲーム開始までの流れがすぐ分かること

### 表示する内容
- 参加 UI
  - 自分の名前の入力テキストボックス
  - 決定ボタン
- 待機者一覧
  - 自分が分かる表示
  - 各参加者の名前
  - 接続状態
  - 参加人数表示
    - 例: `2/6`
- 共有 URL
  - URL 表示ボックス
  - URL コピーボタン
- 簡潔なルール説明
- ゲーム開始ボタン
  - 2 人以上そろったら押せることを分かるようにする
  - 誰が押しても開始できる前提で扱う

### ルール説明
- 手札 2 枚と場札 5 枚から最強の役を作る
- 2 人以上そろうとゲームを開始できる
- 各ハンドは SB / BB を置いて進行する

### 方針
- 待機画面は参加準備、共有、開始の導線を優先して見せる
- 待機中に必要な情報だけを表示し、説明は短く保つ
- ルール説明は初見ユーザが流れをつかめる最小限にとどめる
- `/` と内容を重ねすぎず、待機画面ではプレイ前に必要な要点だけを伝える

## ゲーム画面
### 目的
- いまのラウンドで必要な判断を、スマホの縦画面で迷わず行えること
- 情報量の多いポーカー画面でも、常時表示する情報を絞って見やすさを保つこと

### 基本方針
- 画面が小さいため、すべての情報を常時表示しようとしない
- 常時表示するのは、そのラウンドでアクション判断に必要な情報に絞る
- それ以外の情報は折りたたみや簡易表示に寄せる
- 同じ情報を複数箇所に重ねて表示しない
- プレイヤー一覧は簡易表示を基本とし、詳細情報は必要なときだけ展開する

### レイアウト
- ヘッダ固定
  - 進行ラウンド
  - pot
  - 自分の位置
  - 現在手番
- メイン表示
  - 自分の手札
  - 公開済みの場札
  - プレイヤー一覧
- フッタ固定
  - アクション UI
  - 現在の進行を短く伝える補助文

### 常時表示する内容
- 自分の手札
  - 業種
  - 会社名
  - 数値
- 公開済みの場札
  - 未公開のカードは伏せカードとして表示する
- 進行ラウンド
- pot
- 自分の位置
- 現在手番
- 自分が選べるアクション
- プレイヤー一覧の簡易表示
  - 名前
  - stack
  - このラウンドでのベット額
  - Dealer / SB / BB
  - 手番中かどうか
  - fold / all-in など、そのラウンド中の状態
  - 相手も 2 枚持っていることが分かる伏せカード 2 枚

### 折りたたみや簡易表示に寄せる内容
- 順位
- 接続状態
- side pot の詳細
- 詳しいルール説明
- そのラウンドの判断に直接必要ない補足情報
- プレイヤー一覧の詳細情報

### 優先順位
- 自分の手札を最優先に表示する
- 次に場札を表示する
- プレイヤー一覧は、その下に簡易表示で置く
- 画面が狭い場合でも、手札と場札とアクションは優先して残す

### アクション UI
- ポーカー用語は基本的に表示せず、初心者向けの短いラベルを使う
- アクションは状況に応じて表示内容を変える
- 主な操作は以下を基本とする
  - `降りる`
  - `参加`
  - `上乗せ`
  - `全額`
- `参加` は状況に応じて `check` または `call` に対応させる
- `上乗せ` は状況に応じて `bet` または `raise` に対応させる
- `上乗せ` は自由入力を設けず、数値ベースの候補のみを表示する
  - `bet` では pot に対する割合をそのまま数値で表示する
  - `raise` では現在の基準額に対する倍率や金額をそのまま数値で表示する
- ラウンドが進む条件を自然に伝える補助文を入れる
  - 例: 全員の参加額がそろうと次に進む

## `between_hands`
### 目的
- 前のハンド結果を確認し、次のハンド開始までの待機を分かりやすくすること

### 方針
- `between_hands` は進行中のゲーム画面とは別の専用セクションとして扱う
- ハンドとハンドの間なので、進行中ハンド用の情報は表示しない
- `game_over` は `between_hands` の派生表示として扱う
- 通常の `between_hands` は次ハンド待ちを扱う
- `game_over` 時は最終順位表示と待機画面への導線を表示する

### 表示する内容
- 前のハンド結果
- 勝者
- 各プレイヤーの stack の増減
- ready 状況
- 次ハンド開始待ちの案内
- `game_over` 時は最終順位
- `game_over` 時は待機画面へ戻る導線

### 表示しない内容
- 自分の手札
- 場札
- 進行中ラウンド用のアクション UI
